# Scope plan / decision served / why / project context

**Decision served (exact):** which UI/UX component primitives, HTML/CSS platform components, typography system, and adaptive-layout mechanisms PlayMusicPrompts adopts, builds or avoids when the whole web interface is rebuilt from scratch at the world's most advanced level (Berk's orders of 2026-09-09 14:28 "en baştan dünyadaki en ileri seviyede yap ve mobil web tablet adaptive responsive olmak zorunda tüm fontlar yazılar stiller en ileri seviyede html elementleri ile olacak" and 14:40 "önce araştır en ileri seviyede UI UX componentlarını en ileri seviyede olanları bul, html componentları").

**Why:** the current interface (deploy/payload, Next.js 16 / React 19, three.js 0.186) was measured today to use `<dialog>` 0, `<search>` 0, `<hgroup>` 0, `<output>` 0, `<meter>` 0, `<progress>` 0, `<time>` 0, `<fieldset>` 0; `@layer` 0, `@scope` 0, `text-wrap` 0, `oklch` 0, `font-variation-settings` 0, view transitions 0; the webfont is a render-blocking Google Fonts `@import`. Berk judged the result "10000 üzerinden 1". The rebuild must start from what the frontier actually is, not from recollection.

**Project context:** PlayMusicPrompts — a free, no-credits Music Creation OS: prompt-to-music composition through the Ideasets engine (103 request parameters, live capabilities endpoint), a public catalogue (46 tracks in production Postgres, 22 DB functions), one persistent listening queue, radios, and THE WORLD (a three.js camera journey with five stations). Dark theme on Berk's order (D-PMP-08); brand = the approved logo (D-PMP-10: black stage, volumetric violet→magenta→cyan glass, "PlayMusic|Prompts", CREATE · CONTROL · FEEL). Surfaces: `/`, `/musics`, `/t/<id>`, `/world`, `/login`, `/signup`, `/legal`. Users: listeners and prompt-first creators on phone, tablet and desktop; Flutter apps exist separately. Constraints: WCAG 2.2 AA floor, 24×24 px targets, reduced-motion alternative, 320 px reflow, no paid vendor without approval (Google/AWS/Anthropic pre-approved), English artefacts.

**Downstream action:** a design-system and component rebuild (typography system, semantic HTML per surface, adaptive layout, component primitives) implemented in deploy/payload and deployed; every finding here becomes an ADOPT/BUILD/AVOID line with a file-level application.

## Reversal / falsification evidence

- A platform primitive claimed Baseline is shown by MDN/caniuse/WPT as unsupported in a shipping Safari or Firefox → it moves from ADOPT to BUILD-WITH-FALLBACK or AVOID.
- A component library claimed accessible fails WAI-ARIA APG keyboard patterns or screen-reader tests in a primary source → AVOID.
- Academic evidence that dark-UI or fluid type harms legibility for the target population beyond WCAG floors → design constraint changes.
- Measured font-loading strategy with `next/font` not eliminating layout shift → typography plan changes.
