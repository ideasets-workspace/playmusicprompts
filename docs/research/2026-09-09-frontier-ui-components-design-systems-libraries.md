## Conformance reference — WAI-ARIA 1.3 and APG

- **WAI-ARIA 1.3 is a W3C Working Draft dated 04 June 2026** (not a Recommendation); Editor's Draft 20 August 2026. Changes since FPWD include `ariaNotify` API (PR #2577 merged 2026-02-11, implemented in WebKit and Blink 140, Gecko pending), `sectionheader`/`sectionfooter` roles, prohibition of `aria-hidden=true` on document root. **WAI-ARIA 1.2 remains the Recommendation to conform to.** [PRIMARY FACT, S44,S45,S46]
- **APG is a living guide.** APG Task Force minutes 2026-08-19 show active PRs: #3461 spin-button `ariaNotify` progressive enhancement (live region fallback), #3449 "Three Combobox Examples: Expand on click and improve filter behavior", #2991 colour-contrast settings practice page. [PRIMARY FACT, S47]
- **APG Combobox pattern (read in full this run):** popup may be listbox/grid/tree/dialog; four autocomplete modes (`none`, list-manual, list-auto, `both` inline); DOM focus stays on the combobox with `aria-activedescendant` for listbox/grid/tree popups; `aria-controls` (not `aria-owns`), `aria-expanded`, `aria-haspopup` only when popup ≠ listbox, `aria-selected` on the highlighted option; Alt+Down opens without moving focus; "IMPORTANT: Ensure JavaScript does not interfere with browser-provided text editing functions". This is the contract the prompt field / genre / language Combobox must satisfy. [PRIMARY FACT, S01]

## Five-part academic record — S48 Karlsson (2021), Linnaeus University `[FULL]` on method and results
1. **Problem in the authors' framing:** component libraries are used to build "hundreds of thousands of projects", yet "we have not found much research with the sole purpose of examining the accessibility in React UI component libraries"; an accessibility defect in a library is replicated into every product that uses it.
2. **Method:** controlled experiment; six open-source React libraries selected by GitHub-dependents intervals (>100,000; 5,000–10,000; 1,000–5,000; collected 2021-04-16); one UI per library with the same components (accordion, text input, checkbox, radio, slider, select); automated pass with Axe browser extension (unique issues only), 14 manual APG-1.1-derived test cases (Tables 4.1–4.6), exploratory NVDA 2020.4 testing on Chrome 90 at 1000×1230.
3. **Real numbers (Table 5.1, Table 5.26):** total 50 issues = 22 automated + 14 manual + 14 exploratory. Per library (auto/manual/exploratory/total): React Bootstrap 1/2/2/5; Ant Design 3/2/2/7; **Chakra UI 1/0/0/1**; Grommet 1/1/2/4; PrimeReact 8/2/4/14; **React Suite 8/7/4/19**. Manual test-case pass rates: Chakra 14/14; Grommet 13/14; React Bootstrap, Ant Design, PrimeReact 12/14; React Suite 7/14.
4. **Stated limitations (authors'):** six libraries and a few components only; desktop Chrome only, no mobile; free Axe only. **Analyst limitations:** 2021 data (WCAG 2.1 / ARIA 1.1), pre-dates Base UI and React Aria Components; bachelor thesis, supervised but not peer-reviewed; the libraries tested are styled, not headless.
5. **Application to PlayMusicPrompts:** the experiment's mechanism — the same six widgets, an automated pass, an APG keyboard test-case pass, and an NVDA exploratory pass — is the acceptance protocol the rebuild should run against whichever library is adopted, and it is exactly the three-pass shape the 2026 Disability World audit and Railing use; the "every library had ≥1 issue" finding means adoption never removes the duty to test our own wrappers (thefrontkit found 14/48 shadcn wrappers regress the underlying Radix behaviour through styling).

# Synthesis — adopt / build / avoid (knowledge; final pick is a decision)

**ADOPT (one primitive library as the behaviour layer):** the evidence supports exactly two candidates and no third.
- **Base UI 1.8.0** — for: monthly cadence Jan–Sep 2026, MIT, smallest whole-package cost of the full-inventory libraries (143.5 kB gzip), Combobox/Autocomplete/Select-multi/Drawer/Toast/NumberField/Slider/Menu inventory that maps 1:1 onto our Combobox, Segmented, Dialog/sheet, command palette, toast, tabs, tooltip, player transport and nav rail; shadcn default (reference wrappers public); Spotify reportedly uses it. Against: no independent APG audit found (C7); no Date/Tree/Grid (not needed by PMP today); Apache vs MIT irrelevant for us.
- **React Aria Components 1.21.1** — for: the widest APG inventory (Tree, Grid, Date/Number, TokenField for prompt fields, NavigationTree, Virtualizer), first-party pattern test utilities, independent audit pass (S27), i18n/RTL depth (110 languages is a real requirement), React Spectrum S2 proves it carries a full React-19-only design system. Against: largest whole-package footprint (267.7 kB gzip) and largest open-issue count (610); positioning fixes still landing for iOS 26 in Sept 2026; Apache-2.0.
- **Committed recommendation (INFERENCE, veto path open):** React Aria Components, because for a worldwide 110-language product the i18n/RTL depth and the *independent* audit evidence outweigh the size difference, and its Virtualizer + ComboBox multi-select cover the 2,196-genre list without a second virtualiser; Base UI is the equal-quality alternative if the parent weighs bundle size and MIT higher. **If the parent picks Base UI, C7 must be closed by our own three-pass audit before launch.** The choice is not a taste decision under rule 14; it is an engineering decision the parent may make from this evidence.

**BUILD (on the adopted library's hooks or on native platform features):** Dial and KeyWheel (no library ships a circular slider except Zag's `angle-slider`; build with the adopted library's `useSlider`/`useMove` or a hand-rolled ARIA `slider` role validated by the three-pass protocol); the glass material (rule 14 OWNER-DECISION for values; Apple's Regular/Clear + controls-layer knowledge applies); simple single-value selects as native `<select>` with `appearance: base-select` progressive enhancement; native Popover API / CSS anchor positioning are **not** used by any candidate library's overlay layer today (S04, S09 — positioning is JS in all three), so a from-scratch popover on the platform API remains the only way to get top-layer + zero-JS positioning — at the cost of re-implementing focus, dismiss and ARIA that the libraries already ship (Dev Encyclopedia S53 recommends native only for Tooltip/simple Popover and a library for menus/selects).

**AVOID:** Radix Themes (styled/opinionated); shadcn styled source (brand + rule 14); cmdk (18 months unreleased); vaul (unmaintained by author); sonner as a second toast owner; downshift and react-select (redundant / slow); Headless UI as base (inventory + cadence); Radix Primitives as the *greenfield* base (no Combobox; two React-19 regressions fixed in June–July 2026) — while explicitly recording that it is **not** dead.

**Falsifiers:** an independent APG audit of Base UI (would remove C7 and likely tie the recommendation); a React Aria release adopting CSS anchor positioning / Popover API natively (would remove the BUILD rationale for popovers); a Radix Combobox primitive (would re-open Radix).
