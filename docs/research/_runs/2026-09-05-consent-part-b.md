# Findings — Google mechanics (scope item 2), each line traceable to a downloaded doc
- **EU User Consent Policy** applies "only to end users located in the EEA, the UK, or Switzerland"; last updated 31 July 2024 (CH); publishers must adopt a **Certified CMP** to serve ads there; advertisers must pass consent via Consent Mode or TCF — `google-consent/google-eu-user-consent-policy-help.txt` L7, L8, L10, L15, L16, L29. Certified-CMP list + TCF 2.3 deadline 1 Mar 2026: in-repo `docs/external-api/google-ima/gam-consent-management-requirements-eea.html`, `gam-tcf-publisher-integration.html` (not redone).
- **Consent Mode v2**: `default` before any `config`/`event` (`tag-platform-consent-mode-setup.txt` L128–L136); four purposes `ad_storage`, `ad_user_data`, `ad_personalization`, `analytics_storage` (L132–L135); `wait_for_update: 500` for async CMP (L140–L149); **region scoping** — default without `region` governs all other regions (L368), most specific region wins (L389–L395), ISO 3166-2 sub-regions such as `US-CA` (L393–L408); basic vs advanced (L89–L97); `ads_data_redaction` (L157). Behaviour-modelling thresholds: NOT in this doc — `[GAP]`.
- **UMP (Android/iOS)**: call `requestConsentInfoUpdate` on every launch (`admob-android-privacy-ump.txt` L271; iOS L266); `getPrivacyOptionsRequirementStatus()==REQUIRED` → show entry point (Android L320–L332); gate ads on `canRequestAds()` (Android L343; iOS L337); debug geography `DEBUG_GEOGRAPHY_EEA` (Android L412), iOS `geography` (search excerpt names EEA/UK/CH); **US states message**: UMP ≥ 2.1.0 (`admob-android-privacy-us-states.txt` L235), `setTagForUnderAgeOfConsent(true)` suppresses the request (L217, L249) and is NOT forwarded to the GMA SDK — set TFUA on ad requests too (L255); GPP keys `IABGPP_GppSID`/`IABGPP_HDR_GppString` (L283); `UMPDebugGeographyRegulatedUSState` (iOS US-states page, search excerpt). Flutter surface: in-repo `google-ima/admob-flutter-privacy-ump.html`, mirrored in `app/lib/src/data/consent_gate.dart` L60–L76.
- **ATT ordering (iOS)**: UMP IDFA explainer "before the ATT alert"; `NSUserTrackingUsageDescription` required; ATT shows once; ads may still be requested after denial without IDFA — `admob-ios-privacy-idfa-att.txt` L213–L242.

# Findings — geo-detection (scope item 3)
- Server-side, no vendor: `CloudFront-Viewer-Country` (ISO 3166-1 alpha-2) plus `CloudFront-Viewer-Country-Region` (first-level ISO 3166-2 subdivision — yields `US-CA`, `CA-QC`), delivered to the origin through an **origin request policy** without polluting the cache key; NOT set for requests originating from the AWS network — `google-consent/aws-cloudfront-adding-cloudfront-headers.txt` L28, L71–L83, L76. Next.js middleware on EC2 reads the header and emits the region-scoped `gtag('consent','default',{…,'region':[…]})` block into the HTML head (server-rendered) so the default is region-correct before any tag fires.
- On device: UMP itself decides "whether consent is required" for the device's geography (`admob-android-privacy-ump.txt` L271 ff.); the app does not need its own geo lookup for the ads path; the mechanism Google uses is undocumented — `[UNVERIFIED]`.
- Unknown country (header absent/AWS-origin/`ZZ`): the lawful default is the strictest tier (opt-in, all denied) because Google documents that the region-less default is the catch-all (L368) and no primary read permits default-on universally.
